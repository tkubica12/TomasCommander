# Direction

Tomas Commander is a personal Windows workspace, not an operating system
replacement or a supported commercial file manager.

## Priorities

1. Keyboard-first file work, dependable navigation, clear focus and fast local
   response. Commands/voice come second; mouse interaction remains supported.
2. Native Rust reading/editing and convenient development/agent launchers.
3. Carefully bounded AI commands and discovery, then useful source-linked
   answers through explicitly configured services.

## Future work

- Incremental type-to-focus, remappable shortcuts and better physical CZ/US,
  DPI and accessibility coverage.
- Drag autoscroll, optional folder-hover navigation and reviewed incoming
  Explorer drops. Outgoing native file dragging already offers Copy only.
- Saved-place ordering, reader fit preferences and search scope/history.
- Broader workload-bound startup, memory and input-to-display measurements.
  Rust/native rendering is a design choice, not proof of a speed guarantee.
- Generalize the narrow AI pilots only with explicit data/cost boundaries and
  real end-to-end evidence. Complete WebIQ acceptance before claiming it works.
- Design and authenticate a real WorkIQ integration; no current workplace
  connector is claimed.
- Voice integration after its privacy, lifecycle and provider choices are made.

The initial browser design lab and per-session acceptance diaries have been
removed from the source tree. Production tests and current implementation
policies remain. New substantial features should define observable acceptance
checks before implementation; missing authorization or live proof is not PASS.
